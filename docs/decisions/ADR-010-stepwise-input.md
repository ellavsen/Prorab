# ADR-010. Пошаговый ввод — основной путь, черновик хранится в базе

**Статус:** принято, Sprint 4.

**Контекст.** Единственным способом добавить позицию была строка
«Наименование, количество, цена». Формат компактный, но требует помнить порядок
полей, не ошибаться в запятых и знать, что единицу можно приписать к количеству.
На объекте, с телефона, это неудобно; а неоднозначность запятой (ADR-011) в этом
формате неустранима в принципе.

**Решение.**

1. После выбора категории бот предлагает два пути: **«Добавить по шагам»**
   (по умолчанию) и «Ввести списком». Свободный формат никуда не делся — он
   быстрый путь для тех, кто им владеет.
2. Шаги: наименование → количество → единица → цена → **предпросмотр с
   подтверждением**. В смету ничего не попадает без показа человеку — тот же
   принцип, который заявлен для LLM в тезисе проекта.
3. Единица выбирается кнопкой из справочника. Кнопка «Пропустить» ставит
   значение по категории и **сообщает об этом**: подстановка видима (ADR-006).
   Обязательный шаг удлинил бы ввод десяти позиций на десять нажатий.
4. Если количество введено с единицей («150 м2»), шаг единицы пропускается сам.
5. **Черновик живёт в таблице `user_state`**, а не в `context.user_data`.

**Почему черновик в базе.** `context.user_data` из python-telegram-bot умирает
вместе с процессом ровно так же, как умирали глобальные словари до Sprint 2.
ADR-005 вводился потому, что рестарт молча уводил позиции в другую смету; терять
наполовину введённую позицию — та же болезнь в меньшем масштабе. Цена решения —
шесть nullable-колонок и запрос на шаг; при нагрузке телеграм-бота это ничто.

**Альтернативы.** `ConversationHandler` из python-telegram-bot хранит состояние
в памяти приложения и требует persistence-бэкенда, чтобы пережить рестарт — то
есть ту же базу, но через ещё один слой абстракции.

**Следствия.** Появилась команда `/add` — явный вход в пошаговый ввод.
Свободный текст обрабатывается одной точкой входа `positions.on_text`, которая
смотрит на `draft_step` и решает, шаг это или строка позиции. Хендлеры принимают
`message`/`query`, а не `Update`, поэтому проверяются заглушками без поднятия
Telegram — тесты пошагового ввода не требуют ни токена, ни сети.
