# ADR-004. Деньги и количества хранятся целыми в минимальных единицах

**Статус:** принято, Sprint 1. Переносит ADR-M1 из `docs/money.md` в код.

**Контекст.** SQLite не имеет точного десятичного типа. Проверено на схеме,
которую создавал проект:

```sql
CREATE TABLE positions (qty NUMERIC(18,3), price NUMERIC(18,2));
-- typeof(qty), typeof(price) -> ('real', 'real')
```

То есть деньги лежали в binary float ещё до всякой арифметики, и `Decimal`
«восстанавливался» из уже испорченного значения.

**Решение.** `price_kop INTEGER`, `qty_milli INTEGER`, `rate_bp INTEGER`
(600 = 6.00%). В домене — только `Decimal`. Конвертация строго на границе
репозитория: `to_kop`/`from_kop`, `to_milli`/`from_milli`, `to_bp`/`from_bp`.

**Альтернативы.** Хранить `Decimal` текстом — теряются сортировка и сравнение в
SQL. Сменить СУБД — несоразмерно задаче.

**Следствия.** Миграция `migrate_money_to_integers()` переводит существующие
данные и ведёт журнал строк, чьё REAL-значение не совпало с копейками. Старые
колонки `qty`/`price` удаляются. Сравнения и лимиты в SQL остаются честными:
поиск дубля идёт по `price_kop`, а не по float.
