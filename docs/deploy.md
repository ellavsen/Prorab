# Развёртывание

> **Три конфига отсюда не запускались ни разу.** `Dockerfile`,
> `docker-compose.yml`, шаблон nginx и юниты systemd написаны и вычитаны, но
> `docker compose build`, `nginx -t` и `systemd-analyze verify` на них не
> прогонялись: машины, на которой это можно сделать, пока нет. Поэтому первый
> запуск — **проверка, а не формальность**: считайте, что вы прогоняете эти
> файлы впервые, потому что так оно и есть. Что не сойдётся — правьте здесь же.
>
> Всё остальное в этом документе проверено: команды бота, поведение при
> отсутствии ключей, путь базы, сборка PDF из установленного пакета.

Два разных дела под одной обложкой. §1 — «запустить у себя», чтобы посмотреть:
одна команда, ни одного ключа. §2 — «поднять для людей»: домен, TLS, база,
которая переживает обновление, и журнал, из которого не утекают ссылки на чужие
сметы.

Если вам нужно первое, второй раздел можно не читать вовсе.

---

## Что вообще разворачивается

Три процесса из одного образа и один статический сайт, который разворачивается
сам:

| Процесс | Чем занят | База | Секреты | Наружу |
|---|---|---|---|---|
| `bot` | Telegram, long polling | пишет | токен, ключ AI | нет, ходит сам |
| `share` | публичная страница сметы по ссылке | почти только читает | нет | да, через nginx |
| `api` | расчёт по HTTP | не касается | нет | по желанию |
| `web` | демо | — | — | GitHub Pages, из CI |

Три факта отсюда пригодятся дальше:

- **Схему базы создаёт бот, и только он.** `apps/share/database.py` не вызывает
  `bootstrap` намеренно: сервис, отдающий данные наружу, не должен иметь причин
  менять схему. На чистой машине первым запускается бот.
- **`api` не касается базы вовсе** — это его главное свойство (ADR-008), и
  поэтому ему нечего терять при перезапуске и нечего монтировать.
- **`share` пишет ровно два вида отметок** — просмотр и согласование
  (ADR-020). Это важно для SQLite: писателей на деле полтора, а не два.

Фоновых задач нет ни одной. Ротация смет (последние пять черновиков на
пользователя) и срок жизни ссылки в 30 дней проверяются при обращении, а не по
расписанию, — ставить cron не нужно.

## §1. Запустить у себя

```bash
docker compose up
```

Всё. Поднимутся `api` на `127.0.0.1:8001` и `share` на `127.0.0.1:8000`,
`http://127.0.0.1:8001/docs` покажет Swagger.

**Ключи для этого не нужны, и это не случайность, а требование.** Человек,
пришедший посмотреть проект, не станет заводить бота у @BotFather. Поэтому бот
вынесен в отдельный профиль compose: без `TELEGRAM_BOT_TOKEN` он падает
намеренно (`bot/config.py`), а сервис в рестарт-петле выглядит как сломанный
проект, даже когда всё в порядке.

Бот — когда ключи есть:

```bash
cp .env.example .env          # вписать TELEGRAM_BOT_TOKEN от @BotFather
docker compose --profile bot up
```

`OPENAI_API_KEY` остаётся необязательным и здесь: без него AI-слой работает на
стабе, голос и фото отвечают заранее записанным, а всё остальное — как обычно.

> Пока бот ни разу не стартовал на этой базе, таблиц в ней нет, и `share`
> ответит ошибкой на попытку открыть ссылку. Сами ссылки при этом тоже взяться
> неоткуда — выдаёт их бот. `/healthz` работает в любом случае.

Демо в compose нет — см. «[Чего здесь нет](#чего-здесь-нет)».

## §2. Прод: один VPS

Расчёт на одну машину: бот, `share` и `api` в compose, nginx перед ними, база —
файл SQLite на томе. Этого хватает с запасом, и §«[Когда это перестанет
работать](#когда-это-перестанет-работать)» говорит, когда именно перестанет.

### Что нужно от машины

Небольшой VPS: 1 vCPU, 1 ГБ памяти, 10 ГБ диска. Docker с плагином compose.
Домен, A-запись которого указывает на этот адрес, — до выпуска сертификата.
Системных зависимостей нет: PDF собирается чистым Python, а шрифт едет внутри
пакета (ADR-021), LibreOffice нужен только тестам паритета в CI.

### 1. Код и окружение

```bash
git clone <repo> /opt/prorab && cd /opt/prorab
cp .env.example .env
chmod 600 .env
```

В `.env` — четыре значения, и два из них в проде обязаны отличаться от
образца:

```ini
TELEGRAM_BOT_TOKEN=1234567:AA...
OPENAI_API_KEY=sk-...                      # необязателен
ESTIMATE_DB_URL=sqlite:////data/estimate.db
SHARE_BASE_URL=https://smeta.example.com
```

**`SHARE_BASE_URL` — самая тихая ошибка во всём развёртывании.** По умолчанию
там localhost, ссылка соберётся, `/send` отработает, заказчик получит адрес,
который открывается только на самом сервере. Ничего не упадёт и никто не
сообщит.

**Четыре слэша в `ESTIMATE_DB_URL` — не опечатка.** `sqlite:///data/...` это
относительный путь, `sqlite:////data/...` — абсолютный. С тремя база молча
создастся внутри контейнера и исчезнет при первом обновлении.

### 2. Первый запуск — с бота

```bash
docker compose --profile bot up -d
docker compose logs -f bot
```

Именно в таком порядке: схему создаёт бот. Дальше порядок неважен.

### 3. nginx и TLS

```bash
cp deploy/nginx/prorab.conf.example /etc/nginx/sites-available/prorab
# заменить smeta.example.com на свой домен
ln -s /etc/nginx/sites-available/prorab /etc/nginx/sites-enabled/
certbot certonly --webroot -w /var/www/certbot -d smeta.example.com
nginx -t && systemctl reload nginx
```

**Это не косметика и не «ну, https».** ADR-020 §6 требует, чтобы токен не
попадал в журнал, и приложение своё обещание выполняет: путь режется до
`/e/***`. Но nginx пишет собственный лог, и в нём по умолчанию — полный путь.
То есть **каждая строка обычного access.log была бы рабочей ссылкой на чужую
смету** — в файле, который уедет в архив, в систему сбора логов и в тикет со
скриншотом. ADR это честно называет и оставляет развёртыванию; шаблон в
[deploy/nginx/](../deploy/nginx/) — то место, где обещание наконец
выполняется целиком.

Поэтому же `share` в compose слушает только `127.0.0.1`. Порт, открытый в мир
напрямую, обошёл бы и TLS, и фильтр лога.

### 4. Бэкап

База — один файл на томе `prorab-data`. Копировать его `cp` на работающей
системе нельзя: получится середина транзакции.

```bash
docker compose exec share \
  python -c "import sqlite3,sys; \
             s=sqlite3.connect('/data/estimate.db'); \
             d=sqlite3.connect('/data/backup.db'); s.backup(d); d.close()"
docker compose cp share:/data/backup.db ./estimate-$(date +%F).db
```

`.backup` берёт согласованный снимок на живой базе — этим он и отличается от
копирования файла.

Что в этой базе лежит: сметы, суммы, ставки и Telegram-идентификаторы
владельцев. Про заказчиков — только две отметки времени, ни адресов, ни
браузеров (ADR-020 §8). Хранить бэкапы соответственно.

### 5. Обновление

```bash
git pull
docker compose build
docker compose --profile bot up -d
```

Миграции применяются при старте бота, отдельного шага нет. Том переживает
пересборку — на то он и именованный.

## Вариант без Docker

Если Docker на машине нежелателен, в [deploy/systemd/](../deploy/systemd/)
лежат три юнита. Раскладка та же: код в `/opt/prorab`, база в
`/var/lib/prorab`, пользователь `prorab`.

```bash
useradd --system --home /opt/prorab prorab
install -d -o prorab -g prorab /var/lib/prorab

cd /opt/prorab
python3.13 -m venv .venv
.venv/bin/pip install -r requirements.txt
.venv/bin/pip install .          # без -e: в прод едет то же, что в образ

cp deploy/systemd/*.service /etc/systemd/system/
systemctl daemon-reload
systemctl enable --now prorab-bot prorab-share prorab-api
```

`ESTIMATE_DB_URL` в этом варианте — `sqlite:////var/lib/prorab/estimate.db`.
nginx настраивается ровно так же.

`pip install .` без `-e` здесь принципиален. Editable-установка читает файлы из
исходного дерева, поэтому недостающий `package-data` в ней не проявляется
никогда — а в обычной проявляется сразу, отсутствующим шрифтом на первом же
PDF. Так это однажды и было; теперь ловится тестом
`test_every_runtime_asset_is_declared_as_package_data`.

## Проверка после развёртывания

Пять вещей, каждая из которых ломается тихо:

1. `curl -s https://smeta.example.com/healthz` — отвечает.
2. Сертификат живой, `http://` редиректит на `https://`.
3. В боте: `/new`, позиция, `/send`, `/link` — **и полученная ссылка
   открывается с телефона**, а не только с сервера. Это проверка
   `SHARE_BASE_URL`, и другой у неё нет.
4. `tail /var/log/nginx/prorab.access.log` — на месте токена стоит `/e/***`.
   Если виден токен — лог уже утёк, ротировать ссылки (`/relink`).
5. `/pdf` — приходит файл. Это проверка того, что шрифт доехал в установку:
   без него `build_pdf` не отдаёт документ с «?» вместо букв, а падает с
   `TTFError` на первом же вызове. («?» — это другой случай: символ вне
   урезанного набора, ADR-021.)

## Чего здесь нет

- **Демо (`apps/web`) не входит в compose.** Мастер-план предполагал его там,
  но демо — статическая сборка, которую CI публикует на Pages, и держать её в
  compose значило бы пересобирать колёса Pyodide на каждый `up` ради файлов,
  уже лежащих в интернете. Локально: `npm run dev` (README, «Запуск»).
- **Бот работает через long polling, не через webhook.** Так написан
  `bot/app.py`. Webhook — это правка кода, а не настройка развёртывания, и
  здесь его нет намеренно.
- **Реплик нет.** Почему — ниже.

## Когда это перестанет работать

SQLite и один процесс-писатель — сознательный потолок, а не недосмотр. Он
кончится на одном из трёх:

- **вторая машина.** Файловая база не разделяется между хостами. Это переезд на
  PostgreSQL, а не смена конфига (`ESTIMATE_DB_URL` — один и тот же вход, но
  миграции писались под SQLite);
- **`database is locked` в логах.** Бот и `share` пишут в один файл. `share`
  пишет редко и мало — две отметки, — поэтому конфликт маловероятен, но если
  он появился, первый шаг дешёвый: включить WAL один раз на файле,
  `PRAGMA journal_mode=WAL;`. Настройка живёт в самой базе, перезапуск её не
  сбрасывает;
- **несколько владельцев на одном боте.** Ротация в пять черновиков —
  на пользователя (`RETENTION_LIMIT`), и на объём базы это влияет линейно.

Пока ничего из этого не наступило, одна машина — правильный ответ.
