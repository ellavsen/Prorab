# Прораб — AI-сметчик в кармане

> Смета голосом. За 30 секунд. С объекта.

**[Открыть демо](https://ellavsen.github.io/Prorab/)** — смета считается прямо во
вкладке, бэкенда нет.

**LLM превращает речь, фото и текст в структуру. Деньги считает код.**

ИИ работает только на границе ввода и всегда через предпросмотр с подтверждением.
Ядро расчёта — детерминированное, на `Decimal`, покрытое тестами.

## Как считаются деньги

Единственный источник истины — `calculate_estimate()` в [packages/smeta_core/](packages/smeta_core/).
Ни бот, ни Excel не считают сами: они показывают её результат.

```
factor   = 1 + ставка/100
base     = round2(количество × цена)      ROUND_HALF_UP
line     = round2(base × factor)
subtotal = Σ base,  total = Σ line,  наценка = total − subtotal
```

Итог — сумма **уже округлённых** строк, поэтому «сложить строки глазами» и
«посмотреть Итого» даёт одно и то же число. Формулы в XLSX — транскрипция той же
схемы (`=ROUND(D4*E4,2)`, `=ROUND(F4*(1+$B$1/100),2)`), а не второй расчёт.

Деньги — только `Decimal`; в SQLite хранятся целыми (`price_kop`, `qty_milli`),
потому что `NUMERIC` там физически REAL. Наценка живёт в самой смете, а не в
глобальной константе: смена ставки не переписывает уже выставленные сметы.

Подробности: [docs/money.md](docs/money.md), решения — [docs/decisions/](docs/decisions/).

## Ввод

Основной путь — по шагам: наименование → количество → единица (кнопкой) →
цена → предпросмотр с подтверждением. Ничего не попадает в смету, пока человек
не увидел сумму. Черновик хранится в базе, поэтому перезапуск бота посреди ввода
не стоит набранного.

Быстрый путь — списком:

```
Гвозди 3,5 мм, 100, 20
Уголок 30, оцинкованный, 5, 100
Побелка, 150 м2, 3000
```

Читаются два последних поля — количество и цена, всё остальное слева —
наименование, поэтому запятые внутри названий допустимы. Если строку можно
прочитать двумя способами и суммы расходятся (`Побелка, 150,5, 3000` — это 5
или 150,5?), бот показывает оба варианта и спрашивает, а не выбирает молча
([ADR-011](docs/decisions/ADR-011-robust-parser.md)).

Наценка задаётся на смету: `/rate 6`, либо раздельно `/rate работы 10` и
`/rate материалы 0`. Меняется только активная смета — уже выставленные остаются
как были.

## Голос, фото и живая речь

Отдельных команд нет: наговорите голосовое или пришлите фото накладной, и бот
покажет, что понял.

```
Услышала: побелка сто пятьдесят квадратов по три тысячи,
          гвозди тысяча штук по двадцать

Распознала позиций: 2. Наценка 6,00%.

1. Побелка — работа
   150 м² × 3000,00 = 477000,00
2. Гвозди — материал
   1000 шт × 20,00 = 21200,00

Итого по этим позициям: 498200,00

В смету пока ничего не добавлено. Добавляем?
[🗑 1] [🗑 2]  [✅ Добавить 2] [Отменить]
```

Модель отдаёт **строки**, а не деньги: `Decimal` появляется только после
проверки доменом, и позиция с `qty = -5` не пройдёт ту же валидацию, что и
опечатка человека. В смету не попадает ничего до нажатия «Добавить» — это
проверяется тестом, а не обещается в README
([ADR-012](docs/decisions/ADR-012-llm-at-the-input-boundary.md)).

Схема ответа вложенная, потому что **«цена не названа» ≠ «цена ноль»**:
у количества и цены есть `status`, а у цены ещё и `scope` — «по семьсот» это
за штуку или за всё. Плоское поле слило бы эти случаи, и `missing` уехал бы
в расчёт нулём.

Три вещи, которые модель делать не должна и не делает:

| | |
|---|---|
| **Не считает** | «комната три на четыре» — это не 12 м². Площадь не названа, количество `missing`. Проверяется примером с явным запретом |
| **Не делит** | «на тридцать тысяч за всё» остаётся тридцатью тысячами: строка схлопывается в «Покраска (7 комнат), 1 компл × 30 000». Разделить можно кнопкой «÷», и она сначала покажет, что 7 × 4285,71 = 29 999,97 — на три копейки меньше сказанного |
| **Не выдумывает единицу** | «20 мешков» останется мешками. Канон хранится рядом, отдельным полем, и в документ заказчику идёт сказанное ([ADR-015](docs/decisions/ADR-015-spoken-units.md)) |

Строка, которую разобрать не удалось, показывается с причиной, а не исчезает.
Позиция, слов которой не было во входе, не показывается вовсе. Строгий формат
из раздела выше по-прежнему главный: если он сработал, позиции добавляются
сразу, без предпросмотра пачки.

**Без ключей всё это работает на стабе** — распознавание изображает регулярка,
бот честно пишет «DEMO-режим». С `OPENAI_API_KEY` включаются `whisper-1` для
речи и `gpt-4.1-mini` со строгой JSON-схемой для извлечения и фото; отдельного
OCR нет, накладную читает та же модель
([ADR-013](docs/decisions/ADR-013-provider-roles.md)).

## Подсказка цены — из вашей же истории

Цену прораб называет не всегда: «цемент, мешков двадцать — а по чём, сейчас
гляну». Такая строка не пропадает и не считается нулём, а ждёт цену. И если
это уже покупалось, бот напоминает, по чём:

```
⚠️ 2. Цемент М500 — цена не названа
    💡 вы брали по 380,00 ₽/мешок — 12 марта, 4 раза за полгода; чаще всего 370,00
[💡 Взять цену 2] [Медиана 2]
```

**Ни одного выдуманного числа.** Справочника «типовых цен» в проекте нет и не
будет: цемент по 7 300 там, где у прораба 5 800, закрывает бота навсегда, и
пометка «справочная» этого не меняет. Подсказка берётся только из цен, которые
человек **вводил сам** — его поставщик, его регион
([ADR-017](docs/decisions/ADR-017-price-hint-starts-with-your-own-history.md)).

| | |
|---|---|
| **Не подставляет** | цена появляется в строке по нажатию. До него строка негодная и в сумму не входит — ровно как всё, что приходит от модели |
| **Не смешивает единицы** | цена за м² не предлагается строке в м.п. А вот «мешков» и «мешок» — одно и то же слово в падежах, и это единственный случай, где канон не требуется |
| **Не молчит о сроке** | «за полгода» — не оборот речи: выборка ограничена окном, всё старше не попадает в подсказку вовсе ([ADR-018](docs/decisions/ADR-018-thresholds-are-hypotheses.md)) |
| **Не подглядывает** | только свои цены, `user_id` стоит в каждом запросе. Пересечение историй между людьми — это краудсорсинг, он в Sprint 6b и требует отдельного решения |

Ретеншен хранит пять смет, остальные удаляет. Раньше вместе с ними исчезали и
цены; теперь перед удалением они переписываются в `price_history` — пять полей
вместо документа со связями. Это **меньшее хранение, а не новое**: тот же
`user_id`, который уже есть у позиций, и ни одного другого персонального поля —
это проверяется тестом по схеме, а не обещанием.

Рядом лежит справочник на 173 позиции: канон, единица, категория, синонимы —
и **ни одной цены**. «цемент М500», «ЦЕМ II 42.5», «цемент пятисотый», «м500
мешок 50 кг» — одна позиция; «арматура 12 мм» и «арматура 16 мм» — разные, и
это важнее. Доступен и снаружи: `GET /catalog/lookup?name=ЦЕМ+II+42.5`.

## Насколько хорошо оно распознаёт

В [tests/eval/dataset.jsonl](tests/eval/dataset.jsonl) — 90 размеченных примеров:
расшифровки речи, тексты накладных, свободный ввод, примеры без позиций вовсе —
и попытки увести модель с задачи инструкцией внутри разбираемого текста.

Метрика — точное совпадение после нормализации: количество, цена, их статусы,
`scope`, канон единицы и категория сравниваются точно, наименование — с
точностью до регистра, пробелов и «ё». Считаются обе стороны: пропущенная
позиция бьёт по recall, выдуманная — по precision.

```bash
python scripts/run_eval.py --stub      # нижняя граница без модели
python scripts/run_eval.py             # проигрывание записанных ответов
python scripts/run_eval.py --compare v2 v3.1c   # две версии промпта на одном наборе
OPENAI_API_KEY=... python scripts/run_eval.py --record
```

Ответы модели записываются один раз и дальше проигрываются: CI получает
детерминированный прогон, который при этом меряет настоящую модель, а не
заглушку. Ключ записи включает версию промпта — поменять промпт и не
перезаписать замер не выйдет
([ADR-014](docs/decisions/ADR-014-eval-on-recorded-answers.md)). Записи старых
версий не удаляются, поэтому любую версию можно проиграть заново, не откатывая
код.

### Качество AI-слоя

`gpt-4.1-mini`, 90 примеров, 102 эталонные позиции:

| | стаб | промпт v2 | **промпт v3.1c** |
|---|---|---|---|
| recall | 0.000 | 0.812 | **0.922** |
| precision | 0.000 | 0.812 | **0.922** |
| примеров разобрано целиком | 0 | 67 | **79 из 90** |

Нижняя граница — **ноль**, и это честнее маленького числа: голая регулярка
достаёт наименование, количество и цену, но работу от материала не отличает, а
категория входит в ключ сравнения. Значит всё, что выше нуля, — вклад модели, а
не харнесса.

Три тега — не порог, а **условие**: `injection`, `negative`, `garbage`. Там
извлекать нечего, поэтому любая выданная позиция означает не промах точности, а
послушание чужой инструкции внутри разбираемого текста. Допустимо только
1.000, и оно выполнено — вместе с явными запретами примеров вида «эти числа не
должны появиться в ответе».

Правки промпта проверяются тем же прогоном, а не на глаз
([`--compare`](scripts/run_eval.py) на общем подмножестве версий):

| поле расхождения | v2 | v3.1c |
|---|---|---|
| unit | 5 | **0** |
| category | 1 | **0** |
| qty.value | 1 | **0** |
| price.scope | 8 | **5** |
| позиция выдумана | 4 | **2** |
| позиция пропущена | 4 | **2** |
| нарушенных запретов | 3 | **0** |
| qty.status | 0 | 2 |

Так же видны и провалы, и они не переписываются задним числом. Версия v3
подняла извлечение, но сломала защиту от инъекций (`injection` 1.000 → 0.500).
Версия v3.1b правила два оставшихся дефекта — и увела recall 0.882 → 0.824,
разрешив заодно позиции без цены вовсе; из четырёх её правок в v3.1c взяты две,
которые померены как рабочие. Обе отклонённые версии остались в
`tests/eval/fixtures/` и проигрываются командой выше без отката кода.

Что осталось незакрытым и почему — [docs/known-issues.md](docs/known-issues.md),
все 11 примеров с цифрами. Переразметка набора —
[docs/eval/dataset-notes.md](docs/eval/dataset-notes.md).

Ровно то же ловится и вторым, независимым от промпта способом: позиция без
количества не проходит границу домена **ни при каком содержимом** — это
свойство под hypothesis, а не текст в промпте. Промпт деградирует при смене
модели, `to_position` — нет.

## Структура

```
packages/smeta_core      чистый домен: только stdlib и Decimal
packages/smeta_storage   SQLAlchemy, миграции, репозиторий
packages/smeta_export    XLSX с живыми формулами
packages/smeta_ai        граница ввода: речь, фото и текст → кандидаты
packages/smeta_prices    справочник позиций и подсказка цены (без цен в файле)
apps/bot                 Telegram-адаптер, тонкие хендлеры
apps/api                 FastAPI без состояния
apps/web                 демо: то же ядро в WebAssembly
```

Один расчёт, четыре потребителя. Telegram, HTTP, Excel и браузер показывают
результат `calculate_estimate` — и ни один из них не считает сам.

Правила слоёв не пожелание, а тест: [tests/test_architecture.py](tests/test_architecture.py)
разбирает AST и падает, если ядро потянет за собой telegram или sqlalchemy, если
деньги умножатся вне `calculate.py`, или если файл перевалит за 300 строк.

## Запуск

```bash
python -m venv .venv && source .venv/bin/activate
pip install -r requirements.txt
pip install -e .                    # ставит пакеты ядра и приложения
```

**Бот:**

```bash
cp .env.example .env                # вписать TELEGRAM_BOT_TOKEN от @BotFather
python -m bot.app
```

**API** — без состояния, ни базы, ни секретов:

```bash
uvicorn api.main:app --reload       # документация на http://127.0.0.1:8000/docs
```

Схема в [docs/openapi.json](docs/openapi.json); CI падает, если она разошлась с
кодом. Деньги передаются строками (`"159.16"`) — JSON-число это double, и
копейки на границе терялись бы (см. [ADR-008](docs/decisions/ADR-008-api-contract.md)).

**Демо локально:**

```bash
python scripts/prepare_web_assets.py   # собирает колёса ядра для браузера
cd apps/web && npm install && npm run dev
```

> На macOS `pip install -e .` может «пройти», оставив пакеты неимпортируемыми:
> Python 3.13+ пропускает `.pth` с флагом `hidden`, а его иногда получает всё
> дерево `.venv`. Лечится `chflags -R nohidden .venv && pip install -e .`;
> тест `test_installed_distribution_is_importable` ловит это явно.

## Тесты

```bash
pip install -r requirements-dev.txt
pytest --cov=smeta_core --cov=smeta_storage --cov=smeta_export --cov=smeta_ai --cov=api
ruff check .
vulture packages apps scripts --min-confidence 80
```

1224 теста, покрытие ядра и справочника 100%, AI-слоя — 99%. Среди них прогон на 10 000
случайных смет, проверяющий, что Telegram, сводка и Excel дают одинаковый итог
до копейки.

Отдельно проверяется, что **браузер считает тем же кодом**: одни и те же векторы
прогоняются в CPython и в настоящем Pyodide, расхождение в копейку роняет сборку,
и демо не публикуется.

```bash
cd apps/web && npm run conformance
```

Тест `test_e1_libreoffice_recalculation_matches` пропускается, если LibreOffice
не установлен: без него пересчитать формулы нечем. Ровно так же
`test_recorded_answers_meet_the_threshold` пропускается без записанных ответов
модели — и падает, если запустить его с `REQUIRE_EVAL_FIXTURES=1`, чтобы
«не проверено» нельзя было спутать с «проверено».
